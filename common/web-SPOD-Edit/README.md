# web-SPOD-Edit — объединённая страница: подготовка REPORT + заполнение SPOD

Одна локальная страница, в которой живут две программы:

| Вкладка | Программа | Исходник | Что делает |
|---|---|---|---|
| **Подготовка REPORT** (по умолчанию) | web-report | `common/web-report/` | турниры → источники (CSV/Excel) → ФИО/табельные → дубли → CSV/XLSX REPORT, обновление текущего REPORT |
| **Заполнение SPOD** | web-fill (fill-full) | `common/web-fill-full/` | конкурсы: параметры, группы, индикаторы, связи и награды, расписание → снимок JSON и 6 CSV для SPOD |

Пользовательский путь по обеим программам (все сценарии с вариантами) — **[`Docs/WEB_SPOD_EDIT_USER_GUIDE.md`](../../Docs/WEB_SPOD_EDIT_USER_GUIDE.md)**. Полные технические справочники программ — `common/web-report/README.md` и `common/web-fill-full/README.md` (+ `common/web-fill/README.md`): логика в объединённой странице та же.

## Открытие

Двойной клик по **`web_spod_edit.html`** — страница откроется в браузере (`file://`), ни сервер, ни интернет не нужны. Сверху — тонкая панель:

```
[SPOD web-SPOD-Edit]      [ Подготовка REPORT | Заполнение SPOD ]      [● Лог ⤓ 0 🗑]
```

- **вкладки** по центру: нажатие показывает программу целиком, с её собственным интерфейсом (панели, кнопки, модалки); стрелки ←/→ на вкладках тоже переключают;
- при открытии всегда активна **«Подготовка REPORT»**;
- справа — общий **трейс-лог** (см. ниже).

Каждую программу можно открыть и отдельно, без оболочки: `report/report_app.html`, `fill/game_fill_settings.html` (у fill отдельно нет переключателя лога — лог пишется из оболочки).

## Устройство

```
common/web-SPOD-Edit/
  web_spod_edit.html     оболочка: панель вкладок + два iframe
  shell.css, shell.js    вид (как у web-fill-full) и логика оболочки
  spod_trace.js          общий трейс-лог (оболочка — хозяин журнала, фреймы — источники строк)
  report/                web-report как есть (report_app.html, report_*.js, report_styles.css, xlsx.full.min.js, examples/)
  fill/                  web-fill-full как есть (game_fill_*.html/js/css, catalog.js/.json) + fill_trace_hooks.js
  README.md              этот файл
```

**Почему фреймы, а не одна общая разметка.** Программы написаны независимо и конфликтуют, если их слить в один документ: fill-full — обычные глобальные скрипты (`$`, `render`, `initTips`, `setSidebarOpen`, `toast`… в глобальной области), у web-report совпадающие CSS-классы (`.app`, `.sidebar`, `.chip`, `.btn`, `.panel`, `.modal-card`) и id (`btn-sidebar-hide`, `btn-filters-show`, `glassTip`, `workspace`…). Каждая программа во **своём `iframe`** — отдельный документ со своими скриптами, стилями и id: ничего не переписано, логика не тронута.

- Оба фрейма загружаются **сразу** при открытии страницы. Переключение вкладок только показывает нужный фрейм (`visibility`), поэтому оно мгновенное, а всё, что загружено/заполнено в каждой программе (турниры, файлы, справочник ФИО, конкурсы, фильтры, открытые окна), **сохраняется** при переходах туда-обратно.
- Скачивание файлов (CSV, XLSX, JSON) работает из фреймов как обычно.
- Модальные окна программы открываются внутри её области (под панелью вкладок).
- Каталог fill под `file://` берётся из встроенного `catalog.js` (`fetch` к `catalog.json` браузер под `file://` не выполняет — это ожидаемо, так же, как у отдельного fill-full).

### Защита от потери данных

Данные программ живут в памяти страницы (у fill — ещё черновик в `localStorage`, ключ `spod_web_fill_full_project_v2`, общий с отдельным fill-full). Поэтому:

- **«Назад» по истории перехвачен оболочкой** (`history.pushState`-страж + `popstate`): свайп двумя пальцами по трекпаду, Cmd+[ / Cmd+←, кнопка мыши «Назад» не выгружают страницу — показывается уведомление «Назад отключён». web-report внутри своего фрейма держит такой же страж (26.63).
- Закрытие/перезагрузка вкладки браузера при наличии турниров в web-report — подтверждение браузера (обработчик `beforeunload` web-report срабатывает и во фрейме).

## Трейс-лог (все области)

`spod_trace.js` — развитие `report_trace.js` web-report на всю страницу. Подключается первым скриптом в оболочке и в обеих программах (атрибут `data-area`: `shell`, `report`, `fill`).

| Режим | Когда | Что делает |
|---|---|---|
| **хозяин** | страница открыта сама (оболочка; или программа отдельно) | хранит единый журнал в `localStorage` (`spod_edit_trace_log`; каждая запись сразу — переживает внезапную перезагрузку), управляет переключателем «Лог»/скачать/очистить, при старте отмечает оборванную прошлую сессию (`spod_edit_trace_alive`) |
| **вложенный** | программа во фрейме оболочки | ловит события своего документа и отправляет строки хозяину (`postMessage`); включён/выключен — по сообщению от хозяина; свой переключатель (у web-report) прячет |

- Формат строки: `время [область сессия #номер] КАТЕГОРИЯ: сообщение | данные mem=…`, например `[fill 751p2 #5] ACTION: ← saveProjectFile (14 мс)`.
- Что пишется во всех областях: клики, изменения полей (у файлов — имя и размер), ввод печатанием (итог через 0,5 с), служебные клавиши и сочетания с Cmd/Ctrl/Alt, горизонтальные свайпы и прокрутка над полями-числами, кнопки мыши «Назад/Вперёд», раскрытие блоков, ошибки JS и `console.error`, события жизни страницы, шаги по истории.
- Оболочка (`shell`): переключение вкладок (`TAB`), загрузка программ во фреймы, перехват «Назад».
- web-report (`report`): его точки — `renderAll`, `reapplyDataOrigin` (лист/угол и строки до/после), чтение файлов, «Проверить»/«Сформировать», строка статуса.
- web-fill (`fill`): `fill_trace_hooks.js` оборачивает глобальные функции fill-full без изменения их кода — `render`, `boot`, `showStartGate`, `addContest`, `openCopyContestModal`, `onImportProjectFile` (файл и размер), `saveProjectFile`, `exportAll`, `exportOne` (таблица), `resetToCatalogDefaults` — с длительностью; сообщения `toast` — как `STATUS`.
- **При открытии страницы лог всегда выключен.** Включается переключателем «Лог» в панели оболочки — сразу для всех областей. «Скачать» (стрелка с числом строк) отдаёт весь журнал, файл `spod_edit_trace_<дата>_<время>.txt`; «Очистить» (корзина) удаляет журнал, режим не меняет.
- Журнал объединённой страницы — отдельный от журнала отдельного web-report (`spod_web_report_trace_log`): разные ключи хранения.

## Синхронизация с исходными программами

Исходники остаются в `common/web-report/` и `common/web-fill-full/` — дорабатываются там же. Перенести изменения в объединённую страницу:

```bash
python3 src/Tools/sync_web_spod_edit.py          # копировать report/ и fill/ как есть + подключить лог
python3 src/Tools/sync_web_spod_edit.py --check  # проверить, что копии не отстали (код возврата 1 — отстали)
```

Утилита копирует файлы байт в байт и только в двух HTML подменяет/добавляет теги скриптов: у web-report `report_trace.js` → `../spod_trace.js` (`data-area="report"`), у fill — `../spod_trace.js` (`data-area="fill"`) перед `catalog.js` и `fill_trace_hooks.js` перед `game_fill_boot.js`. Файлы оболочки (`web_spod_edit.html`, `shell.*`, `spod_trace.js`, `fill/fill_trace_hooks.js`) утилита не трогает.
