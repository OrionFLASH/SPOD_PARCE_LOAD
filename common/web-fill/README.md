# Заполнение SPOD (web-fill)

**Один файл:** `game_fill_settings.html` (HTML + CSS + JS + встроенный каталог).  
Типы полей, варианты и дефолты правятся в **web-edit**, затем синхронизируются сюда.

Вариант с разнесёнными файлами: **`../web-fill-full/`**. Полный каталог параметров из PROM: **`../web-edit-full/`**.

## Как открыть

Откройте `game_fill_settings.html` через **Live Server / HTTP** (тогда подхватывается свежий `catalog.json` рядом).  
Через `file://` используется встроенный `EMBEDDED_CATALOG`.

## Примеры снимков (из PROM SPOD)

Готовые JSON для кнопки **«Импорт JSON»** лежат в **`../examples/web-fill/`** (не в этой папке; сохранения UI сюда не пишутся). Обзор: **`../examples/README.md`**.

| Файл | Содержимое |
|------|------------|
| `../examples/web-fill/curated/spod_fill_example_rewards.json` | 4 индивидуальных накопительных: `09_2026-0_23-1_2` … `_5` |
| `../examples/web-fill/curated/spod_fill_example_tournaments.json` | 4 турнира: `01_2026-1_05-3_1`, `10_2026-0_05-3_1`, `01_2026-0_05-2_4`, `01_2026-1_14-1_1` |
| `../examples/web-fill/curated/spod_fill_example_mixed.json` | Все 8 конкурсов в одном снимке |
| `../examples/web-fill/curated/spod_fill_example_json_arrays.json` | Шаблоны JSON-массивов: `CONTEST_PERIOD`, `FILTER_PERIOD_ARR`, `INDICATOR_FILTER` (несколько наборов) |
| `../examples/web-fill/badges/spod_fill_all_badges.json` | Полный снимок: все конкурсы со связью на `REWARD_TYPE=BADGE` (~374) |
| `../examples/web-fill/badges/spod_fill_badges_schedule_2026.json` | BADGE и в SCHEDULE есть период с `START_DT`, содержащим `2026` |
| `../examples/web-fill/contests/spod_fill_all_contests.json` | **Все** конкурсы PROM SPOD из файлов `CONFIG_RUN_INPUT.json` (листы каталога fill) |

В снимке `REWARD_CODE` и `TOURNAMENT_CODE` — **только окончание** (без `r_`/`t_` и без `CONTEST_CODE`). При открытии fill собирает полный код:

- пустое окончание → `r_<CONTEST_CODE>` / `t_<CONTEST_CODE>` (**без** хвостового `_`);
- непустое → `r_<CONTEST_CODE>_<окончание>` / `t_<…>_<окончание>` (`_` только перед окончанием).

Окончание обычно появляется, если наград/периодов несколько, но не всегда. Примеры: `r_01_…_1` → `1`; `r_09_…` без хвоста → пусто; `t_09_…_4001` → `4001`.

Пустой массив `schedule` / `indicator` / `group` / `badges` **не** дополняется заглушкой при импорте. Фантомные пустые строки из старых снимков отбрасываются. Новый конкурс «с нуля» по-прежнему получает стартовые слоты из каталога.

Пересборка из CSV PROM SPOD, указанных в `config/CONFIG_RUN_INPUT.json` (листы каталога fill; исходных CSV в репозитории нет):

```bash
python src/Tools/export_web_fill_examples_from_spod.py
```

Сверка JSON=CSV по каждому `CONTEST_CODE` выполняется при записи снимка. Полный набор конкурсов — `../examples/web-fill/contests/spod_fill_all_contests.json`.

## Старт

При открытии страницы — экран выбора:

1. **Открыть сохранённые настройки (JSON)** — снимок, ранее сохранённый кнопкой «Сохранить JSON»
2. **Создать новый конкурс с нуля** — один конкурс с дефолтами и описаниями из каталога
3. **Продолжить черновик** — если в браузере есть незавершённый проект (совпадает `catalog_stamp`)

Позже снимок можно снова открыть в блоке «Проект» в нижнем колонтитуле.

## Интерфейс

### Список конкурсов (слева)

- Вкладки: две строки — код и `FULL_NAME`; цвет по статусу турниров в расписании.
- Легенда цветов внизу панели (активный → подведение → завершён → отменён/удалён → нет турниров).
- Оранжевая обводка — только после **правок пользователя**.
- Скрытие списка **не** прячет верхний и нижний колонтитулы.

### Поиск и фильтры (справа)

Панель скрывается отдельно от списка конкурсов. Группы фильтров через **AND**.

- Поиск по коду и названиям (конкурс, награды, турниры). Режимы: **начинается с** / **содержит** (по умолчанию) / **равно** — сравнение с отдельным полем, без учёта регистра.
- **Турниры / Награды / Архив**.
- **ПРОМ / ТЕСТ** — подстрока в `CONTEST_FEATURE.vid` или `CONTEST.TARGET_TYPE` (оба вкл. или оба выкл. — не режем по среде).
- **Бизнес-блок** — хотя бы одно из `CONTEST.BUSINESS_BLOCK`, `CONTEST_FEATURE.businessBlock`, `REWARD_ADD_DATA.businessBlock`. Чипы: KMMMB, KMKKSB, AKMKKSB, CSM, **Остальные** (не эти четыре), **Пусто**. У ITEM в списке слева строка товара смотрит на блок награды.
- **Тип награды** — конкурс виден, если есть хотя бы одна награда выбранного `REWARD_TYPE` (по умолчанию все: Награда / Метка / Товар / Кристалл). **Пусто** — нет наград или `REWARD_TYPE` пустой (вкл. по умолчанию).
- **Статус турнира** — конкурс виден, если есть хотя бы один период с выбранным статусом (по умолчанию АКТИВНЫЙ, ПОДВЕДЕНИЕ ИТОГОВ, ЗАВЕРШЕН). **Нет турниров** — массив `schedule` пуст, ключа нет, либо статус и код пустые (вкл. по умолчанию; иначе `CONTEST_00` не найти).
- **Дата** — date-picker; период матчится, если дата в `[START_DT, END_DT]`. Пустое расписание дату не проходит — сбросьте дату.
- Внизу панели: **«Сбросить все фильтры»** (все чипы выкл., дата пустая) и **«Установить все»** (все чипы вкл., дату не ставит). Поиск не меняется.

### Список слева: товары ITEM

У конкурса с наградами типа **ITEM** (много товаров на одном `CONTEST_CODE`) под строкой конкурса идут сами товары — код и `FULL_NAME`, со смещением. Другие типы (BADGE / LABEL / CRYSTAL) по-прежнему одна строка на конкурс.

- Клик по **конкурсу** — карточка конкурса; в шапке «Связи + награды» товары не вываливаются списком, подсказка выбрать слева.
- Клик по **товару** — открывается эта пара; в шапке конкурс / индикаторы / группы общие, награда только выбранная.
- Поиск по коду или названию товара показывает родителя и подходящие строки.

### Верхний колонтитул (шаги)

1. Конкурс → Индикаторы → Группы  
2. Связи + награды  
3. Расписание  

Подписи в чипах:

| Блок | 1-я строка | 2-я строка |
|------|------------|------------|
| Конкурс | тип | `FULL_NAME` |
| Индикаторы | код · тип · agg | mark · match · value |
| Группы | `GROUP_CODE` · value · **подпись** `GET_CALC_METHOD` | критерии (`GET` / `ADD` / `ADD_2`) |
| Расписание | `TOURNAMENT_CODE` | статус · тип периода |

При >3 групп строка «Группы» расширяется (`top-nav__row--groups-heavy`).

### Копирование

Кнопка **«Копировать в остальные»** (модалка с выбором целей):

- группы — все поля, включая `GROUP_CODE`;
- связи + награды — без смены `REWARD_CODE` у целей;
- расписание — без смены `TOURNAMENT_CODE` у целей.

### Расписание

- Кнопка **«+ добавить турнир»**.
- Сортировка периодов по статусу; цветные чипы статусов.

## Архив

Удаление конкурса, группы, индикатора, турнира или пары «связь+награда» уходит в **архив**.

- В фильтре **«Архив»** — **одна строка на конкурс** (код − R · T · G); внутри — все удалённые части или конкурс целиком.
- Новые удаления того же конкурса **добавляются** в ту же строку.
- **Восстановить…**: всё из архива конкурса или только выбранные типы/разделы.
- Конфликт `REWARD_CODE` / `TOURNAMENT_CODE`: оставить текущую / заменить / восстановить рядом. Группы и индикаторы всегда добавляются.
- В CSV архив не попадает. JSON: `archive` как бандлы (`kind: "bundle"`, `version: 4`); старый формат мигрирует при открытии.

## Возможности

- Каталог: сначала `./catalog.json`, иначе встроенный блок; черновик значений — в `localStorage`
- Подсказки и описания — всегда из каталога
- Даты: календарь + чипы «Начало / Конец года / Бесконечный»; в попапе — «Нач. мес.», «Кон. мес.», «Сегодня»
- Dropdown / list — чипы; длинный список (`INDICATOR_CODE`) — combobox с поиском и группировкой; при наличии `variant_labels` на кнопке **подпись** и мелко **код** (в CSV уходит код)
- **number** — поле ввода числа (`REWARD_COST` по умолчанию `5`)
- Подсветка изменённых полей (относительно baseline)
- Несколько конкурсов; экспорт 6 CSV (`;`, UTF-8 BOM), блок **PROM**
- «Сохранить JSON» / «Импорт JSON» — выгрузка и загрузка значений (+ архив)

## Цепочка шагов

Конкурс → Особенности → Группы → Связи + награды → Индикаторы → Расписание

## 6 CSV

1. `CONTEST (PROM) FORM_FILL.csv`
2. `REWARD (PROM) FORM_FILL.csv`
3. `REWARD-LINK (PROM) FORM_FILL.csv`
4. `GROUP (PROM) FORM_FILL.csv`
5. `INDICATOR (PROM) FORM_FILL.csv`
6. `SCHEDULE (PROM) FORM_FILL.csv`

`CONTEST_FEATURE` / `REWARD_ADD_DATA` / объекты — SPOD-JSON с `"""` у ключей и строк, **числа без кавычек**, без CSV-удвоения кавычек.  
`json_array` (`CONTEST_PERIOD`, `FILTER_PERIOD_ARR`, `INDICATOR_FILTER`) — тот же SPOD внутри, весь блок в **одинарных** кавычках `'[…]'` (пустой `[]` без обёртки).  
«Все 6»: в Chromium — выбор папки; иначе очередь скачиваний.

## Синхронизация каталога

После правок в web-edit:

```bash
python src/Tools/sync_web_fill_catalog.py
```

Обновляются `catalog.json`, `catalog.js` (fill и fill-full) и блок `EMBEDDED_CATALOG` в `game_fill_settings.html`.

Зеркало UI из **web-fill-full** — только если нужно выровнять оба варианта (с 16.16 UX живёт в fill-full):

```bash
python3 src/Tools/sync_web_fill_singlefile.py
```
