# web-edit-full — ревью логики, архитектуры и рекомендации

Дата ревью: 2026-09-25. Код не менялся, документ описывает найденные проблемы и предлагаемые доработки.
Проверено: `game_edit_parameters.html`, `game_edit_app.js` (2649 строк), `game_edit_styles.css`, `game_edit_catalog.json` (12 разделов / 162 поля), `README.md`.

Приоритеты: **P1** — может потерять или испортить данные; **P2** — логическая ошибка или вводящее в заблуждение поведение; **P3** — качество, UX, сопровождение.

---

## 1. Краткий итог

Редактор рабочий, модель «baseline + отпечаток поля» для пометки «отредактировано» продумана. Основные слабые места:

1. Один таймер `saveTimer` используется и для тоста, и для автосохранения — правки могут не попасть в черновик.
2. «Перечитать» сначала стирает черновик и только потом читает файл: при ошибке HTTP работа теряется.
3. Отрисовка карточки молча меняет данные (дата, JSON-колонка, чипы), без пометки «отредактировано».
4. Весь код — один IIFE на 2600 строк, скопированный из `web-edit` и частично из `web-fill`; общих модулей и тестов нет.

## 2. Ошибки и риски потери данных

### P1-1. Общий таймер у тоста и автосохранения
`game_edit_app.js:246`, `:281-282`, `:634-636`

`showToast()` делает `clearTimeout(saveTimer)`, `schedulePersist()` — тоже. Последствия:
- правка → `schedulePersist` (250 мс) → в течение 250 мс любой `showToast(...)` (например «Оставьте хотя бы один вариант», «Дата должна быть…») **отменяет запись черновика**;
- обратный случай: `schedulePersist` отменяет скрытие тоста — тост «залипает» до следующего сообщения.

**Рекомендация:** два независимых таймера (`toastTimer`, `persistTimer`). `persist` через `setTimeout(() => persist({ quiet: true }))`: сейчас `persist` вызывается без аргументов, и на каждую правку показывается тост «Черновик в браузере».

### P1-2. «Перечитать» удаляет черновик до успешного чтения
`game_edit_app.js:2626-2639`, `:611-625`

Три ключа `localStorage` удаляются до `fetch`. Если страница открыта без HTTP (file://) или файла нет, получаем `alert` и пустой экран, а черновик уже удалён.

**Рекомендация:** сначала `fetch` и валидация, затем очистка LS и `applyCatalog`. Текст в `alert` исправить: там указан `./catalog.json`, а читается `./game_edit_catalog.json` (`:619`).

### P1-3. `persist()` без try/catch
`game_edit_app.js:627-632`

`localStorage.setItem` может выбросить `QuotaExceededError` (или ошибку в приватном режиме Safari). Исключение уйдёт в обработчик `input`, и пользователь не узнает, что черновик не сохраняется.

**Рекомендация:** обернуть запись в try/catch и показать заметное предупреждение: «Черновик не сохраняется — выгрузите JSON».

### P1-4. Отрисовка молча меняет данные
- `renderDefaultDateUi` (`:1310-1315`): дефолт даты не в формате `YYYY-MM-DD` (например `4000-01-01 00:00:00` из скана PROM) **обнуляется** при первой отрисовке.
- `syncDefaultUi` для `kind=json` (`:1560-1563`): стирает `default`, `variants` и `variant_labels`.
- `renderDefaultChips` (`:1703`, `:1714-1722`) и `ensureDefaultSelection` (`:1632-1647`): подменяют дефолт первым вариантом.

При загрузке `applyCatalog` рисует до снятия baseline (`:342-349`), поэтому эти изменения не видны как правки, но **попадают в экспорт**. `normalizeCatalogFields` (`:1653`) приводит к норме списки, а даты и JSON-колонки — нет.

**Рекомендация:** вся нормализация — только в `normalizeCatalogFields` (добавить `date` и `json`), рендер данные не меняет. Некорректные значения показывать предупреждением («дефолт не ISO-дата: …»), а не стирать молча.

### P2-5. Кнопка «Перечитать» недоступна на стартовом экране
`game_edit_app.js:308-311`

При пустом рабочем пространстве `btn-reload` получает `disabled`. Но именно на старте «прочитать `game_edit_catalog.json` рядом со страницей» нужнее всего: README описывает этот сценарий, а сейчас открыть можно только через файловый диалог.

### P2-6. «Продолжить черновик» берёт baseline от другого каталога
`game_edit_app.js:575-599`, `:469-480`

`tryRestoreDraft("")` не сверяет штамп, а `loadBaseline()` читает `LS_BASELINE_KEY`, который мог остаться от другого файла. В итоге метки «отредактировано» и «Вернуть» указывают на чужой снимок. Пустая ветка `else { /* … оставляем как есть */ }` на `:591-594` это подтверждает.

**Рекомендация:** хранить baseline и черновик одной записью `{sourceStamp, catalog, baseline}`; при несовпадении — явный вопрос пользователю.

### P2-7. Для `dropdown_custom` с длинным списком нельзя задать свой дефолт
`game_edit_app.js:1573-1574`, `:1410`

Для `dropdown_custom` с ≥16 вариантами монтируется combobox с подсказкой «Свой вариант нельзя», и `pick` принимает только значения из списка. Это противоречит самому типу «Список + свой вариант».

### P2-8. Подписи вариантов связаны с кодами по номеру строки
`game_edit_app.js:2172-2214`

Варианты и подписи — две независимые `textarea`. Если вставить код в середину списка, все подписи ниже сдвинутся на чужие коды, а автоматически это не обнаружить.

**Рекомендация:** редактор пар «код ↔ подпись» (таблица строк с добавлением, удалением и перетаскиванием) или хранение в виде `variants: [{value, label}]`.

### P2-9. `depends_on` — свободный текст без проверки
`game_edit_app.js:111-137`

Таблица, поле и json_key вводятся руками. Опечатку (`REWARD_TYP`) увидит только fill на этапе экспорта: условие никогда не выполнится, и ключ молча пропадёт. В текущем каталоге `depends_on` не используется, но механизм уже включён.

**Рекомендация:** выпадающие списки из разделов и полей каталога, подсветка несуществующих ссылок, поле `equals` — из `variants` целевого поля.

### P2-10. Поле `number` без проверки
`game_edit_app.js:1581-1598`

Для `kind=number` дефолт — обычный текст, можно сохранить `abc` или `1,5`.

### P3-11. Прочее
- Попап даты добавляется в `body` при каждом `syncDefaultUi` (`:1373`). Старые попапы убирает только `renderFields` — утечка DOM при смене типа поля.
- Комментарий на `:243` («baseline… после сохранения JSON») не совпадает с кодом: экспорт baseline не пересчитывает (и tooltip это подтверждает). Нужно выровнять.
- Заголовок файла «Редактор каталога параметров BADGE-формы» (`:1`) устарел.
- Поиск перерисовывает всё на каждый символ без debounce (`:2541`); `afterFieldEdit` на каждую клавишу пересчитывает `countEdited()`, то есть JSON.stringify всех 162 полей (`:807-835`). Сейчас терпимо, при росте каталога заметно.
- Разметка статистики продублирована (`:714-723` и `:824-832`), лучше вынести в функцию.

## 3. Данные каталога (`game_edit_catalog.json`)

| Наблюдение | Рекомендация |

| Смешанные id разделов: `CONTEST`, `REWARD` против `TABLE:GROUP`, `TABLE:INDICATOR` | Зафиксировать соглашение (fill завязан на эти id строками — см. `web-fill-full`) |

## 4. Архитектура и структура

1. **Один IIFE на 2649 строк.** Состояние, рендер, календарь, combobox, тултипы и I/O перемешаны. Логические модули: `state/baseline`, `normalize`, `widgets/date`, `widgets/combobox`, `card`, `nav`, `io`.
2. **Копипаст между UI.** `web-edit` → `web-edit-full` (разница в JS — блоки depends_on и json-meta, в CSS — ~100 строк). Календарь, combobox, `variantGroupKey` и тултипы почти дословно повторены в `web-fill-full/game_fill_model.js`. Копия в `POST/SPOD_PROM/common/web-edit-full` уже расходится с `common/`.
   **Рекомендация:** общий каталог `common/web-shared/` (виджеты и нормализация каталога), который подключают оба UI. `web-edit` оставить тонкой обёрткой либо заморозить. Для POST — генерировать копию скриптом (`sync_post_web_bundle.py`), а не править руками.
3. **Нет тестов.** Для `web-report` есть node-тесты (`src/Tests/test_web_report_core.mjs`); здесь — ни одного. Минимальный набор: `fieldSnapshot` / `isEdited` / `applySnapshotToField` (обратимость), `normalizeCatalogFields` (идемпотентность: normalize(normalize(x)) == normalize(x)), `alignVariantLabels`, `normalizeDependsOn`.
4. **Контракт edit ↔ fill не описан.** Флаги `allow_empty`, `json_required`, `omit_when_empty`, `empty_json_mode`, `json_wrap_quotes`, `depends_on` и `marks` объясняются только в тултипах. Нужен раздел в README (или отдельный `CATALOG_FORMAT.md`): что означает каждый флаг для CSV и JSON и как fill его применяет.
5. **Глобальные `window.__spodActiveDateWrap` / `__spodActiveDatePop`** — использовать замыкание модуля вместо глобалов.

## 5. UX и доступность

- Тултип по `mousemove` на весь документ с `getBoundingClientRect` на каждом движении — лучше `pointerover`/`pointerout` плюс `requestAnimationFrame`. С клавиатуры тултипы не видны; `data-tip` стоит дублировать в `aria-describedby` или `title` для ключевых элементов.
- `alert`/`confirm` — стоит заменить на встроенный диалог (как в fill), чтобы не блокировать страницу.
- Нет подтверждения при закрытии вкладки с несохранёнными правками (`beforeunload`, если `countEdited() > 0` и после экспорта были изменения).
- Нет отмены (undo) для «Вернуть всё». Стоит сохранять снимок перед массовым откатом.
