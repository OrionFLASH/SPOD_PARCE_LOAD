# Заполнение Excel-формы конкурса BADGE

Инструкция для работы с шаблонами **`CONTEST_BADGE_FORM_BLANK.xlsx`** и **`CONTEST_BADGE_FORM_EXAMPLE.xlsx`**.  
Техническое описание режимов export/import: [`CONTEST_BADGE_FORM.md`](CONTEST_BADGE_FORM.md).  
Правка подписей/описаний/дефолтов списков: HTML-редактор [`param_review_editor/index.html`](param_review_editor/index.html).

---

## 1. Какие файлы использовать

| Файл | Когда брать |
|------|-------------|
| **BLANK** | Новый конкурс «с нуля». В репозитории: `Docs/templates/CONTEST_BADGE_FORM/CONTEST_BADGE_FORM_BLANK.xlsx` |
| **EXAMPLE** | Образец заполнения (6 реальных конкурсов из SPOD) — смотреть и копировать приёмы; генерируется в `OUT/…` |
| Свой export | Результат `contest_badge_form_export` по выбранным `CONTEST_CODE` |

Типовые пути после генерации (`contest_badge_form_blank`):

- `OUT/PROM/CONTEST_BADGE_FORM/CONTEST_BADGE_FORM_BLANK.xlsx`
- `OUT/PROM/CONTEST_BADGE_FORM/CONTEST_BADGE_FORM_EXAMPLE.xlsx`

Пересоздать blank + example: в `run_outputs` для блока указать `contest_badge_form_blank`, затем `python main.py`.

## 2. Структура книги

- Листы именуются **`1`**, **`2`**, **`3`**… — один лист = один конкурс.
- В конце книги скрытый лист **`Lists`** — служебные длинные списки для выпадающих; **не редактировать**.
- Версия формы: строка `#META:FORM_VERSION` (сейчас **6**).
- Легенда цветов: строка `#META:LEGEND`.

На каждом листе сверху вниз:

1. `#SECTION:CONTEST` — поля конкурса + `FEATURE.*`
2. `#SECTION:BADGE:1` … (`:2`, `:3` для турнира) — награда BADGE + `ADD.*`
3. Таблицы `#TABLE:REWARD-LINK`, `#TABLE:GROUP`, `#TABLE:INDICATOR`, `#TABLE:SCHEDULE`

---

## 3. Что можно менять

| Столбец / область | Действие |
|-------------------|----------|
| **A** (ключ) | Не менять |
| **B** (подпись) | Можно не трогать |
| **C** и ячейки таблиц | **Заполнять** (цвет = тип ввода) |
| **D** (описание) | Справка; не нужна для импорта |
| Строки `#SECTION:…`, `#TABLE:…`, `#HINT` | Не удалять и не переименовывать маркеры |

Пустые строки в таблицах внизу — запас для новых строк; лишние пустые при импорте игнорируются.

---

## 4. Цвета значений (легенда)

| Цвет | Тип | Как заполнять |
|------|-----|----------------|
| Зелёный | Выбор из списка | Только из выпадающего списка (клик по ячейке → стрелка) |
| Жёлтый | Свободный ввод | Текст / число вручную |
| Персик | Несколько значений | Через **`;`** без лишних пробелов по краям элементов: `KMKKSB;MNS` |
| Розовый | JSON | Как в выгрузке SPOD (фильтры, `GROUP_VALUE`, `FILTER_PERIOD_ARR`, `TARGET_TYPE` в SCHEDULE…) |
| Голубой | Дата | Формат **`YYYY-MM-DD`** (например `2026-09-01`) |

Цвет колонки в таблице тоже показывает тип (см. подсказку в строке `#HINT`).

## 5. Порядок заполнения нового конкурса (BLANK)

### 5.1. CONTEST

1. **`CONTEST_CODE`** — уникальный код (как в SPOD).  
2. **`CONTEST_TYPE`** — из списка:  
   - `ТУРНИРНЫЙ` → до **3** слотов BADGE  
   - `ИНДИВИДУАЛЬНЫЙ` / `ИНДИВИДУАЛЬНЫЙ НАКОПИТЕЛЬНЫЙ` → **1** слот  
3. Даты **`CREATE_DT` / `CLOSE_DT`** (голубые).  
4. Статусы и методы — зелёные списки (`BUSINESS_STATUS`, `TARGET_TYPE`, `FACTOR_MARK_TYPE`…).  
5. **`BUSINESS_BLOCK`** — персик: один или несколько кодов через `;`.  
6. Поля **`FEATURE.*`**: флаги Y/N — зелёные; списки табельных/ТБ/ГОСБ — персик через `;`.

### 5.2. BADGE (слоты)

Для каждого используемого слота:

1. **`REWARD_CODE`**, **`FULL_NAME`**, описания — жёлтые.  
2. **`REWARD_TYPE`** = `BADGE` (список).  
3. **`ADD.*`**: Y/N и справочники — зелёные; **`ADD.feature` / `ADD.businessBlock` / `ADD.helpCodeList`** — персик через `;`.  
4. Неиспользуемый слот турнира можно оставить пустым (без `REWARD_CODE`) — при импорте слот не попадёт в REWARD.

### 5.3. Таблицы

- **REWARD-LINK** — связь `CONTEST_CODE` + `GROUP_CODE` + `REWARD_CODE` (код бейджа из слота).  
- **GROUP** — уровни расчёта; **`GROUP_VALUE`** часто `*` или JSON (розовый).  
- **INDICATOR** — показатели; **`INDICATOR_FILTER`** — JSON или пусто.  
- **SCHEDULE** — периоды турнира; даты голубые; статусы зелёные; JSON-поля розовые.

Во всех строках таблиц **`CONTEST_CODE`** должен совпадать с кодом на этом листе (если не задумано иное).

## 6. Типичные ошибки

| Ошибка | Что будет |
|--------|-----------|
| Поменяли ключ в столбце A | Поле не прочитается / уйдёт не туда |
| В персиковой ячейке запятая вместо `;` | Массив соберётся неправильно |
| В зелёной ячейке значение не из списка | Excel может ругаться; импорт возьмёт как есть — риск для SPOD |
| Дата не `YYYY-MM-DD` | Проблемы в расписании / фильтрах |
| У индивидуального конкурса заполнили BADGE:2–3 | Лишние слоты лучше очистить; лимит — 1 BADGE |
| Не-BADGE в `REWARD_TYPE` | Форма рассчитана только на BADGE |

## 7. Проверка на примере (EXAMPLE)

1. Откройте **EXAMPLE**, лист `1` — накопительный ОСВ.  
2. Сравните зелёные Y/N и персиковые массивы с описанием в столбце D.  
3. Посмотрите таблицы GROUP / INDICATOR / SCHEDULE на том же листе.  
4. Листы `5`–`6` — турниры «Зарплатный рывок» (другой `CONTEST_TYPE` и расписание).

Обратная сборка из EXAMPLE (уже можно повторить у себя):

1. В `config/CONFIG_CONTEST_BADGE_FORM.json` указать:
   - `import_form_path` → путь к EXAMPLE (или к своей заполненной форме)
   - при необходимости `import_output_dir`
2. В `CONFIG_RUN_INPUT.json`: `"PROM": ["contest_badge_form_import"]`
3. `python main.py`

Либо разово из Python / скрипта: `import_form_file(...)`.

Результат: каталог с **xlsx** листов SPOD и **CSV** (`sep=;`, JSON с `"""`).

## 8. Export → правка → Import (рабочий цикл)

```
IN/.../SPOD CSV
      │  contest_badge_form_export
      ▼
  Excel-форма (листы 1..N)
      │  правка цветных ячеек
      ▼
  contest_badge_form_import
      │
      ▼
  OUT/.../ CONTEST, REWARD, … .xlsx + .csv
```

1. Заполните `contest_codes` в `CONFIG_CONTEST_BADGE_FORM.json`.  
2. Export → отредактируйте форму.  
3. Укажите `import_form_path` на отредактированный файл.  
4. Import → проверьте CSV (особенно `CONTEST_FEATURE` и `REWARD_ADD_DATA`).

---

## 9. Краткая шпаргалка по цветам

- **Зелёный** — выбрать, не печатать от себя.  
- **Жёлтый** — писать текст.  
- **Персик** — несколько значений через **`;`**.  
- **Розовый** — вставить JSON как в SPOD (или оставить пустым).  
- **Голубой** — только дата `YYYY-MM-DD`.
