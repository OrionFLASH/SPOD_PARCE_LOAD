# План: web-SPOD-Edit — объединённая страница web-report + web-fill

Пункт **27** в `ROADMAP.md`. Код: `common/web-SPOD-Edit/`. Техническое описание — [`../common/web-SPOD-Edit/README.md`](../common/web-SPOD-Edit/README.md); пользовательский гид — [`WEB_SPOD_EDIT_USER_GUIDE.md`](WEB_SPOD_EDIT_USER_GUIDE.md).

## Задача (от заказчика)

- Две независимые страницы — `common/web-report` и `common/web-fill-full` — объединить в одну, в отдельном каталоге `common/web-SPOD-Edit` рядом.
- Переключение между программами — кнопкой/тонкой вкладкой вверху; переключение открывает полностью готовый интерфейс программы; по умолчанию — web-report.
- Логика и интерфейс обеих программ переносятся **как есть**, ничего не ломая.
- Трейс-лог как у web-report — на все страницы и все области.
- Протестировать, подробная документация и пользовательский путь по обеим программам.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Как объединить | Оболочка `web_spod_edit.html` + **две программы в своих `iframe`** (`report/`, `fill/`) | Программы конфликтуют в одном документе: у fill-full глобальные функции (`$`, `render`, `initTips`, `setSidebarOpen`, `toast`…), у обеих — одинаковые CSS-классы (`.app`, `.sidebar`, `.chip`, `.btn`, `.panel`, `.modal-card`) и id (`btn-sidebar-hide`, `btn-filters-show`, `glassTip`, `workspace`). Фрейм изолирует скрипты, стили и id — код программ не меняется |
| Переключение | Тонкая панель вверху (46 px): сегмент из двух вкладок по центру, в стиле кнопок web-fill-full (заказчику этот дизайн нравится больше); ←/→ на вкладках | Минимум места; вид как у fill-full |
| Загрузка | Оба фрейма грузятся сразу, скрытый — `visibility: hidden` | Переключение мгновенное, у обеих программ сохраняется состояние; fill раскладывается корректно (не `display:none`) |
| По умолчанию | Всегда web-report (не запоминается) | Требование |
| Копии программ | `report/` и `fill/` — байт в байт из исходников, кроме тегов скриптов лога в двух HTML; утилита `src/Tools/sync_web_spod_edit.py` (+ `--check`) | Исходники дорабатываются в своих каталогах; перенос — одной командой, без ручных правок |
| Трейс-лог | `spod_trace.js`: оболочка — **хозяин** журнала (`localStorage`, переключатель, отметка сбоя), фреймы — **вложенные** (строки → хозяину через `postMessage`, состояние — от хозяина); области `shell` / `report` / `fill`; для fill — `fill_trace_hooks.js` оборачивает его глобальные функции (`render`, импорт/экспорт, сохранение и др.) без правки кода | Один журнал на всю страницу, работает и под `file://` (где фреймы — разные «источники» для браузера); прежний API `ReportTrace` сохранён — точки лога web-report работают без изменений |
| Защита данных | Оболочка перехватывает «Назад» (pushState-страж); web-report внутри держит свой страж и `beforeunload` | Один свайп «Назад» перезагрузил бы обе программы |
| Каталог fill | Встроенный `catalog.js` (как у fill-full под `file://`) | `fetch` к `catalog.json` под `file://` недоступен — это уже так работало |
