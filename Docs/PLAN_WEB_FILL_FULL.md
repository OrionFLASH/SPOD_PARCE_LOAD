## 18.1 — Выбор конкурсов для JSON и CSV

### UI левой панели

Рядом с действиями списка (после «Копировать конкурс» или в той же полосе):

1. Кнопка **«Выбрать»** — включает/выключает режим отметки.
2. Рядом две **компактные** кнопки с иконками (без длинных подписей на кнопке, подпись в `data-tip`):
   - **отметить все** — галка / список с галками;
   - **снять все** — пустой квадрат / перечёркнутая галка.
3. В режиме выбора слева от каждой строки конкурса (и строк ITEM под ним — см. ниже) появляется отметка (checkbox).

«Отметить все» отмечает **видимые сейчас** (с учётом фильтров и поиска).  
«Снять все» снимает **все** отметки в сессии, в том числе скрытые текущим фильтром — иначе выбранное «за фильтром» нельзя снять, не меняя фильтр.

Смена фильтра **не сбрасывает** уже выбранное. На другом фильтре можно довыбрать. В выгрузку попадают выбранные **независимо от активного фильтра**.

Строки товара ITEM в списке — часть конкурса: отметка только на **конкурсе**. Клик по товару по-прежнему открывает карточку товара, не переключает выбор.

### Кнопки скачивания (без новых)

Не добавлять отдельные «скачать выбранные». Менять текст существующих:

| Кнопка сейчас | Нет выбора или выбраны все конкурсы сессии | Есть выбор и выбраны не все |
|---------------|--------------------------------------------|-----------------------------|
| «Сохранить JSON» | **Скачать все JSON** | **Скачать выбранные JSON** |
| «Все 6» | **Скачать все CSV** | **Скачать выбранные CSV** |

Допустимо вторую строку мелким текстом: «все N» / «выбрано K из N».

Архив JSON: при «все» — как сейчас (`contests` + `archive`). При «выбранные» — только выбранные конкурсы; архив **не** класть, пока явно не попросят.

CSV по-прежнему только активные конкурсы, без архива; фильтр таблиц — по выбранным `CONTEST_CODE`.

Пустой выбор в режиме «Выбрать»: не писать пустые файлы — toast «Ничего не выбрано».

## 18.2 — Бизнес-блок: один источник

Источник правки: лист **Конкурсы**, поле `CONTEST.BUSINESS_BLOCK`.

На листах FEATURE и REWARD поля `CONTEST_FEATURE.businessBlock` и `REWARD_ADD_DATA.businessBlock`:

- не редактируются (вид как locked-value);
- показывают то же значение, что у конкурса;
- подсказка: «Чтобы изменить — задайте бизнес-блок на странице конкурса».

При смене `CONTEST.BUSINESS_BLOCK` сразу копировать значение во `feature.businessBlock` и во все `badges[].add.businessBlock` текущего конкурса.

В **JSON и CSV** оба зависимых поля по-прежнему присутствуют и заполнены (как сейчас попадают в выгрузку). Пустые значения допустимы, если на конкурсе блок пуст.

Фильтр списка (16.14) не ломаем: после синхронизации три поля совпадают, ИЛИ даёт тот же результат.

## 18.3 — Формат кода награды (в т.ч. ITEM)

### Обычные типы (BADGE, LABEL, CRYSTAL, …)

Как 16.18, без смены правила:

- принцип: `r_` + `CONTEST_CODE` (+ `_` + окончание, если окончание непустое);
- если загруженный код **не** следует принципу — поле целиком;
- новые пары всегда с префиксом `r_`.

### Тип ITEM

- Полный код: `ITEM_` + окончание (код товара), **не** `r_`.
- Создание / смена типа на ITEM: префикс `ITEM_` зафиксирован, вводится только окончание.
- Показ уже загруженных: если код начинается с `ITEM_` — слева литерал `ITEM_`, справа окончание.
- Если префикса `ITEM_` нет — поле целиком (старый/чужой формат), как для `r_`/`t_`.

Смена типа BADGE→ITEM: если код следовал `r_`+CONTEST_CODE — собрать `ITEM_` + прежнее окончание; иначе не переписывать.  
ITEM→не-ITEM: если был `ITEM_` — собрать `r_`+CONTEST_CODE(+`_`+окончание); иначе не переписывать.

Турниры (`t_`) этим пунктом не меняются.

## 18.4 — Полный код в JSON, окончание отдельно

Сейчас в снимках examples в `TOURNAMENT_CODE` / `REWARD_CODE` часто лежит **суффикс** (`4001`). Нужно наоборот.

### Поля снимка (fill JSON)

В строке расписания и в связи/награде:

| Поле | Содержимое |
|------|------------|
| `TOURNAMENT_CODE` / `REWARD_CODE` | Полный код, как в CSV SPOD (`t_CODE`, `t_CODE_4001`, `r_CODE`, `ITEM_99`, …) |
| `TOURNAMENT_CODE_ENDING` / `REWARD_CODE_ENDING` | Только окончание (`""`, `4001`, код товара без `ITEM_`). Нет в CSV SPOD — **только JSON fill**. |

CSV-выгрузка из UI по-прежнему пишет полные коды в штатные колонки, без колонок `*_ENDING`.

Логика UI читает окончание из `*_ENDING`, если оно есть; иначе вычисляет из полного кода. При правке в UI обновляются **оба** поля.

`parentRewardCode` в ADD: полный код; при необходимости отдельное `parentRewardCodeEnding` не вводим в этой волне (раскрывать по тому же правилу, что `REWARD_CODE`).

### Совместимость импорта

Старые снимки (окончание в `REWARD_CODE` / `TOURNAMENT_CODE`, без `*_ENDING`):

- если значение выглядит как окончание (`isSnapshotCodeEnding`) — развернуть в полный код, как сейчас;
- записать вычисленное окончание в `*_ENDING`.

Новые снимки: полный код в штатном поле, окончание рядом.

Экспортер примеров и тесты `test_web_fill_code_ending.py` перевести на полные коды + `*_ENDING`. Пересобрать `common/examples/web-fill/`.

Цель: сопровождение, не микрооптимизация. Без бандлера, порядок `<script>` в HTML, общий IIFE/`window` namespace.

## Проверки приёмки

- Режим «Выбрать»: отметки слева; фильтр А → отметить; фильтр Б → довыбрать; JSON/CSV содержат объединение, без лишних конкурсов.
- «Отметить все» — только видимые; «снять все» — все отметки сессии.
- Подписи кнопок: все / выбранные; второй строки достаточно, отдельных кнопок скачивания нет.
- Смена `CONTEST.BUSINESS_BLOCK` меняет FEATURE и все REWARD; на тех листах поля не кликабельны; в CSV/JSON значения есть.
- ITEM: UI `ITEM_` + окончание; в JSON полный `ITEM_…`; не-ITEM с `r_` без регрессии 16.18.
- Новый JSON: `TOURNAMENT_CODE` = полный; рядом `TOURNAMENT_CODE_ENDING`. Старый JSON с `4001` открывается.
- CSV SPOD без колонок `*_ENDING`.
- После split JS страница fill-full открывается по HTTP, импорт примера и выгрузка работают.
