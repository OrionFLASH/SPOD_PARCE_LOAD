# Пользовательский гид: web-report

Инструкция для тех, кто готовит файл **REPORT** (CSV для загрузки в SPOD) по данным турниров через страницу `common/web-report/`. Здесь — только «как пользоваться», шаг за шагом, на конкретных сценариях. Как страница устроена внутри и полный список форматов/полей — в [`../common/web-report/README.md`](../common/web-report/README.md).

## Перед началом

1. Открыть `common/web-report/report_app.html` **двойным кликом** — страница откроется в браузере. Ничего устанавливать и запускать не нужно — ни сервер, ни интернет не требуются, всё работает локально в браузере.
2. Страница всегда открывается пустой: список турниров слева пуст, правая панель фильтров свёрнута.

Три панели: слева — список турниров, кнопки «Добавить» / «Открыть JSON» / «Сохранить JSON» / «Загрузить списки» / «Справочник ФИО» и внизу — конвейер «Проверить» → «Сформировать» → CSV / XLSX. По центру — параметры выбранного турнира и его источник данных. Справа — поиск, фильтры и статистика; скрывается/раскрывается кнопкой у края.

Справочник ФИО — **один общий на все турниры**, а не отдельный под каждым: кнопка «Справочник ФИО» слева становится активной, как только в списке есть хотя бы один турнир режима FIO, и открывает то же самое окно независимо от того, какой турнир сейчас выбран в центре.

## Сценарий 1. Один турнир вручную, обычный табельный (TN)

Самый простой путь — данные один раз в месяц/квартал по одному турниру, в источнике уже есть табельный номер.

1. Слева — **«Добавить»**. Появится новый турнир с планом `0` и сегодняшней датой; пустые обязательные поля подсвечены оранжевым.
2. В центре заполнить параметры: код конкурса, код турнира, наименование, план, дата данных, тип расчёта — оставить **TN**, период (год/квартал/месяц/произвольный).
3. Блок «Источник данных» → **«Загрузить CSV / Excel»** — выбрать файл с показателями. После загрузки страница покажет строки и список колонок.
4. Если файл Excel и в нём несколько листов — выбрать нужный в поле «Лист» (для CSV поле не показывается — у CSV листов нет).
5. Указать «Стр.» и «Кол.» — строку и колонку левого верхнего угла таблицы, если данные начинаются не с самой первой ячейки (обычно 1 и 1).
6. В полях «Колонка ФИО / табельного» и «Колонка показателя» выбрать нужные колонки из выпадающих списков.
7. При необходимости — «Показатель: действие»: умножить/разделить/сложить/вычесть число перед записью в `FACT_VALUE` (например, ×100, чтобы из доли 0,5 получить 50).
8. Слева внизу — **«Проверить»**: покажет сводку (сколько строк, сколько попадёт в CSV, есть ли проблемы) без выгрузки файлов.
9. Если всё в порядке — **«Сформировать»**, затем кнопки **CSV** и **XLSX** (появляются активными после формирования) сохранят файлы на диск.
10. **«Сохранить JSON»** — сохранить параметры турнира (без данных) на будущее: в следующий раз можно будет открыть этот JSON и не заполнять параметры заново (см. Сценарий 4).

## Сценарий 2. Турнир по ФИО (в источнике нет табельных)

Когда в исходном файле есть только ФИО, а табельный нужно определить по справочнику. Справочник — **один на все турниры FIO**: заполняется один раз в отдельном окне и сразу применяется ко всем турнирам такого типа, а не отдельно под каждым.

1. Добавить турнир (или открыть существующий), в поле «Тип расчёта» выбрать **FIO**. Кнопка **«Справочник ФИО»** на левой панели станет активной (она включена, если в списке есть хоть один турнир FIO — независимо от того, какой турнир сейчас открыт в центре).
2. Загрузить источник как в сценарии 1, но в поле «Колонка ФИО / табельного» выбрать колонку с ФИО.
3. Нажать **«Справочник ФИО»** слева — откроется окно. Справочник можно получить тремя способами:
   - **«Открыть JSON»** в окне справочника — если он уже был сохранён раньше;
   - вручную дополнять по одной записи через диалог «ФИО не найдены» (см. ниже) во время «Проверить»/«Сформировать»;
   - **«Загрузить таблицу ФИО»** — загрузить CSV/Excel со столбцами «ФИО» и «Табельный», выбрать нужные колонки и нажать **«Применить»** (кнопка активна только после того, как файл загружен и обе колонки выбраны).
4. При «Применить» из таблицы: если одно и то же ФИО встречается несколько раз, в справочник попадает **первая** строка сверху с табельным, который состоит только из цифр; если у всех повторов табельный пустой или с буквами — берётся первая как есть. Если после применения показано предупреждение — нажать **«Подробнее»**, откроется список проблемных строк (дубль/пустой/нечисловой табельный) с отметкой, какая строка выбрана.
5. Если турниров FIO несколько — справочник загружается **один раз** в этом окне и участвует в проверке/формировании сразу у всех них; открывать окно заново под каждым турниром не нужно.
6. При **«Проверить»** или **«Сформировать»**, если для кого-то из источника (любого турнира FIO) не нашлось совпадения в справочнике, откроется окно **«ФИО не найдены в справочнике»**: можно вписать табельный (только цифры, до 20 знаков) у каждого имени и нажать **«Дополнить и продолжить»** — записи уйдут в общий справочник и в строки; или сразу нажать **«Продолжить с 00000000»** — тогда у таких строк будет табельный из нулей и флаг «ТАБЕЛЬНЫЙ НЕ НАЙДЕН = ДА» (такие строки не попадут в CSV, но останутся в XLSX с пометкой).
7. Не забыть сохранить справочник (кнопка «Сохранить JSON» в окне «Справочник ФИО») — на следующий раз он не потеряется. Он также сохраняется вместе с турнирами в общем «Сохранить JSON» (см. Сценарий 4) — отдельно сохранять не обязательно, если сохраняете JSON настроек целиком.

## Сценарий 3. Массовая загрузка турниров из выгрузок SCHEDULE / CONTEST / REPORT

Когда нужно завести сразу много турниров (например, все активные турниры блока за квартал), а не по одному руками.

1. Слева — **«Загрузить списки»**.
2. На первом шаге загрузить три CSV (обычно из `IN/PROM/SPOD/` или `IN/PSI/SPOD/`):
   - **SCHEDULE** (список турниров, статусы, период) — обязателен;
   - **CONTEST** (названия и планы) — обязателен;
   - **REPORT** — необязателен; без него дата у всех загруженных турниров будет сегодняшней.

   Под каждой кнопкой появится статус: сколько строк прочитано, или чего не хватает (нужных колонок). Пока `SCHEDULE`+`CONTEST` не загружены — кнопка **«Далее»** неактивна.
3. На втором шаге — список статусов турниров (`TOURNAMENT_STATUS`) из файла SCHEDULE, каждый — с числом строк. Отметить нужные (например, только «АКТИВНЫЙ» и «ПОДВЕДЕНИЕ ИТОГОВ» — обычно «ЗАВЕРШЕН»/«УДАЛЕН»/«ОТМЕНЕН» брать не нужно). Кнопки «Отметить все» / «Снять все» — для быстрого выбора.
4. Если файл REPORT был загружен на первом шаге — тут же переключатель **«Какие турниры брать»**:
   - **«Все»** (по умолчанию) — все турниры с отмеченным статусом, как в пункте 3;
   - **«Только из REPORT»** — дополнительно оставить только те, по которым в загруженном REPORT уже есть хотя бы одна строка (то есть по ним уже реально считались показатели). Удобно, если нужны не все турниры подряд, а именно те, с которыми уже сейчас есть данные для расчёта — остальные можно будет добрать позже отдельно. Счётчик строк под статусами сразу пересчитывается с учётом этого выбора.
5. **«Загрузить турниры»** — появится сводка: сколько загружено, сколько уже было в списке (пропущены как дубли), сколько не прошло по фильтру REPORT (если он включён), сколько требуют проверки.
6. **Важно:** у всех загруженных так турниров галочка **«Включать в проверку и выгрузку» стоит на «нет»** — это сделано намеренно, потому что загружены только параметры (код, план, дата, период), а источник данных по участникам (табельные/ФИО + показатель) к ним ещё не подключён.
7. Турниры с отклонениями (конкурс не найден в CONTEST, план не определился, период не распознан, дата не нашлась в REPORT) помечены в списке слева меткой **«! СПИСКИ»** (фиолетовая рамка) — наведите на метку, чтобы увидеть причину.
8. Дальше с каждым нужным турниром — как в сценарии 1 или 2: открыть его, проверить параметры (особенно те, что были помечены), загрузить источник данных по участникам, включить галочку «Включать в проверку и выгрузку», проверить и сформировать.

## Сценарий 4. Обновить уже загруженный REPORT новыми данными

Когда турниры заведены через «Загрузить списки» (вместе с файлом REPORT), донастроены и проверены — можно не просто скачать новый CSV с нуля, а обновить исходный REPORT: заменить в нём строки готовых турниров, не трогая всё остальное.

1. **Условие доступности:** REPORT был загружен через «Загрузить списки» в этой сессии, и «Сформировать» пройдено с зелёным гейтом CSV (то есть обычная кнопка CSV реально скачала бы файл, а не показала «CSV заблокирован»). Без этого кнопка **«Обновить REPORT»** неактивна.
2. Нажать **«Обновить REPORT»** слева, рядом с CSV/XLSX. Откроется окно со сводной таблицей: по каждому турниру, у которого сейчас есть готовые к выгрузке строки, — сколько строк было в исходном REPORT, сколько станет, сколько табельных ушло из файла, сколько осталось, сколько новых.
3. По умолчанию отмечены все турниры из таблицы. «Отметить все» / «Снять все» — если нужно обновить только часть, например, когда остальные турниры ещё не перепроверены или их пока рано трогать.
4. **«Обновить и скачать»** — у отмеченных турниров прежние строки в REPORT удаляются целиком и заменяются новыми; всё остальное в файле (другие турниры, вся история) остаётся как было. Скачается новый файл `REPORT_<дата>_<время>.csv` — тот же формат, что и у обычного REPORT.
5. Загрузить этот файл туда же, откуда обычно берётся REPORT — для дальнейшей работы или для следующей «Загрузить списки».

**Отличие от CSV/XLSX:** обычные кнопки формируют новый файл только из того, что собрано на странице сейчас. «Обновить REPORT» — про слияние с уже существующим REPORT-файлом: неотмеченное и нетронутое сохраняется как было, обновляется только то, что реально пересчитано и отмечено.

## Сценарий 5. Повторное открытие сохранённого JSON (обновление данных за новый период)

Типичная ситуация: JSON с параметрами турниров уже был сохранён в прошлый раз, сегодня нужно пересчитать по свежим файлам.

1. **«Открыть JSON»** → выбрать сохранённый файл. Страница восстановит все параметры турниров (коды, план, дату, период, выбранные колонки) и справочник ФИО целиком (записи ФИО↔табельный хранятся прямо в JSON) — но **сами файлы источников она подгрузить не может**: страница открыта локально (двойным кликом), а не через сервер, и по правилам браузера не может сама читать другие файлы на диске без явного выбора пользователем. Так что после «Открыть JSON» источник данных у каждого турнира будет не загружен, даже если в прошлый раз всё уже было настроено — это ожидаемо, не ошибка.
2. Для каждого турнира — **«Загрузить CSV / Excel»** заново, как в сценарии 1 (обычно это тот же файл, что и раньше, но со свежей датой в имени — типично для выгрузок PROM, где в имени файла есть дата: было `CONTEST (PROM) 23-09 v0.csv`, стало `CONTEST (PROM) 30-09 v0.csv`). Лист и колонки при новой загрузке сбрасываются — их нужно выбрать заново (если структура файла не менялась, это быстро: те же названия колонок будут в списке).
3. Справочник ФИО восстанавливается **сам, без ручной загрузки** — в отличие от источников турниров, сами записи (ФИО↔табельный) хранятся прямо внутри JSON и приходят вместе с ним. Догружать таблицу ФИО заново нужно, только если появились новые люди или обновились табельные — тогда открыть **«Справочник ФИО»** слева и загрузить свежую таблицу (сценарий 2, п. 3–4): новые записи добавятся к уже восстановленным, а не заменят их.
4. Обязательно пересохранить JSON после обновления, если данные нужно будет открывать ещё раз — так параметры турниров и справочник ФИО не придётся вводить заново, даже несмотря на то, что источники турниров всё равно нужно будет каждый раз догружать вручную.

## Сценарий 6. Копия похожего турнира (например, для нового периода)

Когда новый турнир почти повторяет уже настроенный (те же колонки, тип, только код/название/период другие).

1. Открыть турнир-образец, нажать значок **«Копировать турнир»** у активной вкладки в списке слева.
2. Копия создаётся с теми же параметрами и с уже загруженным источником, но **заблокирована**: в списке она отмечена оранжевой рамкой. Пока код и наименование не изменены, кнопки «Проверить»/«Сформировать» недоступны **для всего списка турниров**, а не только для копии — это сделано специально, чтобы случайно не выгрузить две одинаковые строки под разными кодами.
3. Поменять **и** код турнира, **и** наименование (оба сразу, не совпадать с исходными) — после этого блокировка снимается автоматически.
4. Если для копии нужны новые данные (например, отчёт за новый период) — загрузить новый файл источника через «Загрузить CSV / Excel»: угол и выбранные колонки при этом сбрасываются, их нужно будет выбрать заново (иначе, если структура файла та же, можно оставить как есть).
5. Проверить план и дату — они наследуются от исходного турнира и почти всегда требуют правки под новый период.

## Сценарий 7. Разрешение дублей

Возникает, когда у одного турнира несколько строк с одним и тем же ФИО или табельным (например, сотрудник дважды встретился в источнике).

1. При «Проверить» или «Сформировать» открывается окно **«Дубли»** — по одной группе за раз («Группа N из M»), показан ключ дубля и сумма показателя.
2. По умолчанию отмечена первая строка группы. Кнопки **«Все» / «Снять» / «Первая»** — быстро изменить отметки.
3. Выбрать действие для группы в выпадающем списке:
   - **«Оставить отмеченные»** — в CSV попадёт только отмеченная строка (для CSV можно отметить ровно одну);
   - **«Сумма показателя в одну строку»** — показатели группы складываются в первую строку, остальные исключаются;
   - **«Убрать все из CSV»** — вся группа не попадёт в CSV (в XLSX останется с пометкой).
4. **«Применить и далее»** — переход к следующей группе; когда группы закончились, проверка продолжится. **«Остановить»** — прервать проверку без сохранения решений по оставшимся группам. **«Отмена»** — закрыть окно без изменений.
5. Решения запоминаются: при повторной проверке для уже разобранных групп в окне появится подсказка «ранее: …», и можно оставить как было.

## Сценарий 8. CSV заблокирован — что делать

Если после «Сформировать» кнопка **CSV** осталась неактивна или при попытке скачать появилось окно «CSV заблокирован» — там таблица по турнирам с разбивкой причин и примерами:

| Причина в таблице | Что сделать |
|---|---|
| **Дубли строк** | Пройти диалог дублей (сценарий 7) до конца, для каждой группы оставить ровно одну строку, сумму или исключить всех |
| **ТН≠20 цифр** | Открыть источник, найти строку — типичные случаи: табельный пуст, содержит буквы, длиннее 20 цифр, или в Excel виден как `1.23457E+19` (экспонента — в Excel нужно поставить **текстовый** формат для столбца табельных и заново сохранить/загрузить файл; выгружаемые из web-report XLSX/CSV от этого не страдают — колонка табельного там всегда текст, независимо от формата исходного файла) |
| **Показатель не число** | В колонке показателя есть текст вроде «н/д» или число с посторонними символами — поправить в источнике и загрузить заново |
| **Пустые ячейки** | Одна из 7 колонок для выгрузки пуста у части строк — обычно план, дата или код не заполнены на уровне турнира |

**XLSX при этом всё равно можно скачать** — в нём проблемные строки помечены в колонке `CSV_ERROR`, это самый быстрый способ увидеть все проблемы сразу в одной таблице.

## Сценарий 9. Поиск турнира в длинном списке

Когда турниров в списке слева много (после массовой загрузки — особенно).

1. Открыть правую панель (кнопка-стрелка «Фильтры» у края экрана).
2. **Фильтры-чипы** сверху вниз: «Тип расчёта» (TN/FIO), «В выгрузке» (включённые / выключенные — полезно, чтобы быстро увидеть все турниры, у которых ещё стоит «нет» после массовой загрузки), «Готовность» (готовые / неполные / копии, ожидающие смены кода). Все условия работают одновременно («и»).
3. **Поиск** — строка сверху плюс три режима под ней:
   - **«Содержит»** — найдёт совпадение где угодно в названии/коде;
   - **«Начиная с»** — найдёт по началу слова, даже если это слово не первое в названии (например, «прод» найдёт «Герой продаж»);
   - **«Целиком»** — только точное совпадение всего поля целиком (например, чтобы найти турнир по полностью известному коду).
4. Справа под фильтрами — компактная статистика: сколько турниров всего, активных, заполненных, строк, ошибок и т.д. (подсказки при наведении на каждую цифру).

## Частые вопросы

**После «Открыть JSON» источники не подтянулись сами — это баг?**
Нет, так и должно быть. Страница открыта локально, двойным кликом, без сервера — по правилам безопасности браузера страница с адреса `file://` не может сама читать другие файлы на диске, только те, что пользователь явно выбрал в диалоге загрузки. «Открыть JSON» восстанавливает параметры турниров и справочник ФИО (он хранится в самом JSON), но файлы источников турниров нужно каждый раз загружать вручную заново (см. Сценарий 5).

**Почему я не могу вписать путь к файлу вручную?**
Поле «Путь к файлу» — только информация о том, какой файл был загружен последним, для поля ничего вручную не задают. Раз страница работает без сервера, писать туда путь всё равно было бы бессмысленно — по нему нельзя ничего автоматически найти.

**Пропало поле «Лист» у источника.**
Оно показывается только для Excel-файлов. У CSV листов не бывает, поле скрывается — это ожидаемо. Если файл ещё не загружен вообще, поле есть, но неактивно с подписью «— сначала загрузите файл —».

**Табельный показывает что-то вроде `1.23457E+19`.**
Это симптом **исходного** файла: Excel хранит числа не длиннее 15 значащих цифр — 20-значный табельный, введённый как число, теряет точность и превращается в экспоненциальную запись ещё до того, как файл попадёт в web-report, так что внутри приложения это уже не исправить. Решение: в исходном файле поставить для столбца табельных **текстовый** формат (не числовой), пересохранить и загрузить заново.
Сам web-report так не делает: колонка табельного (`MANAGER_PERSON_NUMBER`) в выгружаемых XLSX/CSV всегда записывается текстом с сохранением ведущих нулей — независимо от того, числовым или текстовым был этот столбец в исходном файле. В `1.23457E+19` может превратиться только то, что вы видите в источнике до загрузки, а не файл, который скачивает сам web-report.

**Кнопка «Справочник ФИО» неактивна — почему?**
Она активна, только если в списке турниров есть хотя бы один турнир режима **FIO** — не важно, включён он в выгрузку или выбран сейчас в центре. Добавьте турнир или переключите «Тип расчёта» существующего на FIO, и кнопка включится.

**У меня несколько турниров FIO — справочник грузить под каждым?**
Нет, ровно наоборот: справочник один на всех. Загрузите таблицу или JSON один раз в окне «Справочник ФИО» — он тут же станет доступен всем турнирам режима FIO при «Проверить»/«Сформировать», без повторной загрузки под каждым турниром.

**Кнопка «Обновить REPORT» неактивна — почему?**
Для неё нужны два условия одновременно: (1) REPORT был загружен через «Загрузить списки» в этой сессии — если списки не загружались вовсе или файл REPORT там не выбирали, обновлять нечего; (2) «Сформировать» пройдено и CSV реально готов к скачиванию (гейт зелёный) — если CSV заблокирован (дубли, плохие табельные и т.п.), сначала нужно их разрешить, как в Сценарии 8.

**Что означает пометка «! СПИСКИ» на турнире?**
Турнир получен через «Загрузить списки», и при сборке параметров что-то не удалось определить однозначно (конкурс не найден, план по умолчанию, период не распознан или дата не нашлась) — наведите на метку, там точная причина. Это не ошибка, а подсказка проверить параметры перед включением турнира в выгрузку.

**Показатель посчитался как 0, хотя в источнике было значение.**
Начиная с текущей версии нечисловой показатель не превращается в 0 — вместо этого строка помечается ошибкой «показатель не число», и CSV блокируется. Если видите именно `0.00000`, значит ячейка в источнике была пустой — это единственный случай, когда пустой показатель действительно превращается в ноль.
