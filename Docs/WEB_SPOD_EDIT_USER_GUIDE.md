# Пользовательский гид: web-SPOD-Edit (подготовка REPORT + заполнение SPOD)

Одна страница — две программы. Здесь — «как пользоваться», шаг за шагом, по сценариям и с вариантами. Устройство страницы и технические детали — [`../common/web-SPOD-Edit/README.md`](../common/web-SPOD-Edit/README.md). Самые подробные описания каждой программы в отдельности: [`WEB_REPORT_USER_GUIDE.md`](WEB_REPORT_USER_GUIDE.md) (web-report) и [`../common/web-fill/README.md`](../common/web-fill/README.md) + [`../common/web-fill-full/README.md`](../common/web-fill-full/README.md) (web-fill).

---

## 0. Как открыть и как устроена страница

1. Открыть **`common/web-SPOD-Edit/web_spod_edit.html`** двойным кликом. Ничего устанавливать не нужно, работает без сервера и интернета.
2. Сверху — тонкая панель:
   - слева — название страницы;
   - по центру — **две вкладки**: **«Подготовка REPORT»** (web-report) и **«Заполнение SPOD»** (web-fill). Активная — синяя;
   - справа — **«Лог»**: переключатель трейс-лога, кнопка скачивания журнала (с числом строк) и корзина (очистить). Подробно — часть C.
3. При открытии всегда активна **«Подготовка REPORT»**.
4. Нажатие на вкладку показывает программу **целиком**, со всеми её панелями, кнопками и окнами. Можно переключаться сколько угодно: **всё, что вы уже сделали в каждой программе, остаётся на месте** — загруженные файлы, турниры, справочник ФИО, результат «Сформировать», открытые конкурсы, фильтры. Программы не мешают друг другу и работают независимо.
5. Переключать можно и с клавиатуры: фокус на вкладке, затем стрелки ← / →.

**Где хранятся данные**

| Программа | Пока страница открыта | Что сохраняется само | Что нужно сохранить вручную |
|---|---|---|---|
| Подготовка REPORT | всё — в памяти страницы | ничего (страница всегда стартует пустой) | «Сохранить JSON» — параметры турниров и справочник ФИО; CSV / XLSX / обновлённый REPORT — кнопками выгрузки |
| Заполнение SPOD | всё — в памяти страницы | черновик конкурсов в браузере (кнопка «Продолжить черновик» на старте) | «Скачать все JSON» — снимок; CSV — кнопками экспорта |

**Защита от случайной потери данных.** Жест/кнопка **«Назад»** (свайп двумя пальцами по трекпаду, Cmd+[, Cmd+←, кнопка мыши) на странице отключены — появится уведомление «Назад отключён», данные останутся. При закрытии или перезагрузке вкладки, если в «Подготовке REPORT» есть турниры, браузер спросит подтверждение. Перед закрытием сохраните нужное (JSON).

**Файлы при скачивании** попадают в обычную папку загрузок браузера, как на отдельных страницах.

## Часть A. «Подготовка REPORT» (web-report)

Цель — из выгрузок турниров и файлов с показателями собрать **REPORT**: CSV для загрузки в SPOD и XLSX с диагностикой, либо обновить текущий REPORT.

### A.0 Экран

- **Шапка программы** — шесть плашек-«светофоров» готовности: Турниры → Поля → Источники → ФИО → Дубли → Выгрузка. Цвет: зелёный — готово, красный — нужно действие, серый — этап не участвует. На каждой — короткие цифры с иконками (сколько всего/в отчёте, файлов, строк с ошибкой, записей ФИО, групп дублей и решено, строк XLSX/CSV). Наведите на цифру — подсказка.
- **Слева** — кнопки «Добавить», «Открыть JSON», «Сохранить JSON», «Загрузить списки», «Справочник ФИО»; ниже — **список турниров** (у каждого — код, название, метки периода/типа/готовности, «! СПИСКИ», статус по датам с днями, мини-статистика строк); внизу — конвейер **«Проверить» → «Сформировать» → CSV | XLSX → «Загрузить REPORT» | «Обновить REPORT»**.
- **По центру** — «Параметры турнира» (галочка «Включать в проверку и выгрузку», даты SCHEDULE и статус справа, коды, название, план, дата данных, тип расчёта TN/FIO, период) и «Источник данных» (загрузка CSV/Excel, лист, строка/колонка начала таблицы, колонки, действие над показателем, превью).
- **Справа** (кнопка-стрелка «Фильтры» у края) — поиск, фильтры (тип, в выгрузке, готовность, статус по датам) и статистика.

### A1. Один турнир вручную, в источнике есть табельный (TN)

1. «Добавить» → появится турнир (план 0, дата — сегодня), пустые обязательные поля подсвечены.
2. Заполнить код конкурса, код турнира, название, план, дату данных, период; тип — **TN**.
3. «Загрузить CSV / Excel» → файл с показателями. Для Excel — выбрать **лист**; при необходимости указать **«Стр.» / «Кол.»** — где начинается таблица (строка заголовков).
4. Выбрать **колонку табельного** и **колонку показателя**. Превью ниже раскрыто — видно, что взято; выбранные колонки подсвечены.
5. При необходимости «Показатель: действие» — ×, ÷, +, − на число (например, ×100 из доли).
6. «Проверить» — сводка без выгрузки (строк, в CSV, проблемы).
7. «Сформировать» — кнопка станет **зелёной «✓ готово»**; любая правка данных снимет отметку.
8. **CSV** / **XLSX** — сохранить файлы. XLSX — книга из нескольких листов: `REPORT`, при участии ФИО — `ФИО`, при загруженном текущем REPORT — `REPORT изменения`.
9. «Сохранить JSON» — параметры на будущее (без самих данных).

*Варианты:* источник без табельного — сценарий A2; несколько турниров — повторить 1–5 для каждого (или A3); CSV заблокирован — A8.

### A2. Турнир по ФИО (в источнике нет табельных)

1. Турнир с типом расчёта **FIO**; в источнике выбрать колонку **ФИО**.
2. Кнопка **«Справочник ФИО»** слева активна, пока есть хоть один турнир FIO, и **оранжевая**, пока справочник пуст. Справочник **один на все турниры FIO** — загружается один раз.
3. В окне справочника: «Открыть JSON» (сохранённый справочник) или «Загрузить таблицу ФИО» (CSV/Excel, лист, строка/колонка, колонки ФИО и табельного) → «Применить». При дублях ФИО берётся первая строка с корректным табельным; «Подробнее» — список проблемных строк.
4. «Проверить»/«Сформировать»: если кого-то нет в справочнике — окно «ФИО не найдены»: вписать табельные («Дополнить и продолжить») или «Продолжить с 00000000» (такие строки не пойдут в CSV). Дубли ФИО — окно решения (A7).
5. В XLSX — лист **«ФИО»**: весь справочник с оценкой, невзятые строки таблицы ФИО, не найденные и дубли ФИО с решением, «табельный в работе».

### A3. Массовая загрузка турниров из SCHEDULE / CONTEST / REPORT

1. «Загрузить списки» → SCHEDULE (обязателен), CONTEST (обязателен), REPORT (необязателен; без него дата данных — сегодня) → «Далее».
2. Отметить статусы турниров (например, АКТИВНЫЙ, ПОДВЕДЕНИЕ ИТОГОВ); при загруженном REPORT — «Все» или «Только из REPORT».
3. «Загрузить турниры» — сводка. Все загруженные — с **выключенной** галочкой «Включать…» (сначала подключить источник); с отклонениями — метка «! СПИСКИ».
4. Из SCHEDULE приходят **даты** старта/завершения/итогов и статус на сегодня: «не стартовал», «активен», «подведение итогов», «пора закрывать», «закроется сейчас», «нет данных» — со счётчиком дней. Периоды: год, кварталы, полугодия (H1/H2), месяцы (включая «турнир месяца» — по месяцу старта), остальное — «Произвольный».
5. Дальше по каждому нужному турниру — источник, галочка, как в A1/A2.

### A4. Обновить текущий REPORT

1. REPORT должен быть загружен: через «Загрузить списки» (A3) **или** кнопкой **«Загрузить REPORT»** (для турниров, добавленных вручную; кнопка неактивна, если REPORT пришёл из списков). Не загружен ни так, ни так — обновлять нечего.
2. «Сформировать» с зелёным гейтом CSV.
3. Посмотреть изменения заранее: XLSX → лист **«REPORT изменения»** (НОВАЯ / УДАЛЕНА; без изменений — «БЕЗ ИЗМЕНЕНИЙ»).
4. «Обновить REPORT» → таблица по турнирам (было / станет / ушло / осталось / новых), отметить нужные → «Обновить и скачать» → `REPORT_<дата>_<время>.csv`.

### A5. Повторное открытие JSON (новый период)

«Открыть JSON» восстанавливает турниры (включая даты SCHEDULE) и справочник ФИО; **файлы источников загружаются заново вручную** (страница не может сама читать файлы с диска). Колонки при новой загрузке выбрать заново. Пересохранить JSON.

### A6. Копия похожего турнира

Иконка «копировать» у активного турнира в списке → копия с теми же параметрами и данными, заблокирована до смены **кода турнира и названия** (подсветка). Проверить план/дату.

### A7. Дубли

При «Проверить»/«Сформировать» — окно по группам: «Оставить отмеченные» (для CSV — одну), «Сумма показателя в одну строку», «Убрать все из CSV». «Применить и далее» / «Остановить» / «Отмена». Решения запоминаются до следующей проверки.

### A8. CSV заблокирован

Окно показывает по турнирам: дубли, неверный табельный (не 20 цифр — с причиной), показатель не число, пустые ячейки + примеры. XLSX всё равно можно скачать — в колонке `CSV_ERROR` все проблемы.

### A9. Поиск и фильтры

Справа: поиск (Содержит / Начиная с / Целиком), фильтры «Тип расчёта», «В выгрузке», «Готовность», **«Статус по датам»** (Не старт / Активен / Итоги / Закрыть / Нет дат — с числом турниров; плюс «Только „закроется сейчас“»). Все условия — одновременно.

### A10. Контроль сроков

Метки статуса с днями в списке, число «пора закрывать» на плашке «Турниры», даты и дни в «Параметрах турнира», фиолетовая «закроется сейчас» — если дата данных позже и завершения, и итогов.

## Часть B. «Заполнение SPOD» (web-fill)

Цель — заполнить параметры конкурсов SPOD (конкурс, особенности, группы, индикаторы, связи и награды, расписание турниров) и выгрузить **снимок JSON** и **6 CSV** для загрузки в SPOD.

### B.0 Экран

- **Сверху (колонтитул шагов)** — чипы шагов текущего конкурса: **Конкурс** (тип · название), **Индикаторы** (код · тип · агрегация), **Группы**, **Связи + награды**, **Расписание** (код турнира · статус · тип периода). Нажатие на чип открывает этот шаг.
- **Слева** — **список конкурсов** (две строки: код и название; цвет — по самому «живому» статусу турниров, легенда внизу; у ITEM — товары под конкурсом); кнопки «Добавить конкурс», «Копировать конкурс», «Выбрать» (+ «отметить все видимые» / «снять все»).
- **По центру** — карточка открытого шага с полями.
- **Справа** — «Поиск и фильтры» (каждый блок — отдельная карточка с мини-кнопками «все» / «снять»).
- **Снизу** — блок **«Проект»** («Импорт JSON», «Скачать все JSON», «Сброс») и **«Экспорт CSV»** («Скачать все CSV» и по одной таблице: CONTEST, REWARD, LINK, GROUP, INDICATOR, SCHEDULE).
- Панели слева и справа скрываются кнопками-стрелками на стыке колонок.

### B1. Старт: три варианта

При первом открытии вкладки — экран **«С чего начнём?»**:
1. **«Открыть сохранённые настройки (JSON)»** — выбрать снимок `spod_fill_….json` (ранее скачанный «Скачать все JSON»; примеры — `common/examples/web-fill/`: `curated/…`, `contests/spod_fill_all_contests.json` и др.).
2. **«Создать новый конкурс с нуля»** — один конкурс с полями и значениями по умолчанию из каталога.
3. **«Продолжить черновик»** — появляется, если в браузере остался незавершённый проект (черновик сохраняется автоматически).

Позже снимок можно открыть снова кнопкой «Импорт JSON» внизу.

### B2. Новый конкурс с нуля — пошагово

1. «Создать новый конкурс с нуля» (или слева «Добавить конкурс», если конкурсы уже есть).
2. **Конкурс** (открывается первым): сверху — **стенд конкурса** (PROM / PSI), затем поля сверху вниз: **тип конкурса** (ТУРНИРНЫЙ / ИНДИВИДУАЛЬНЫЙ / ИНДИВИДУАЛЬНЫЙ НАКОПИТЕЛЬНЫЙ — от типа зависит рекомендуемое число пар «связь + награда»), код, сроки, правила, бизнес-блок; внизу — блок **CONTEST_PERIOD** (периоды расчёта; чип P×N в шапке прокручивает к нему).
   - Поля-списки — чипы; длинные списки (например, `INDICATOR_CODE`) — поле с поиском и группировкой; даты — календарь и кнопки «Начало года», «Конец года», «Бесконечный» (в календаре — «Нач. мес.», «Кон. мес.», «Сегодня»); числа — поле ввода; JSON-поля — редактор.
   - Изменённые относительно исходного значения поля подсвечиваются; у списка слева конкурс с правками получает оранжевую обводку.
3. **«Особенности конкурса (FEATURE) →»** — JSON-колонка `CONTEST_FEATURE`.
4. **Индикаторы** — «Добавить ещё один индикатор», поля индикатора; «В архив» — убрать текущий.
5. **Группы** — «Добавить ещё одну группу», код, значение, способ расчёта и критерии; «В архив».
6. **Связи + награды** — каждая пара «связь + награда» — вкладка; «добавить связь + награду» (подсказка напомнит рекомендуемое число для типа), поля связи и награды (тип награды, код, стоимость и др.), **«Особенности награды (ADD_DATA) →»** — JSON `REWARD_ADD_DATA`; «Копировать в остальные» — параметры активной пары в выбранные другие (коды наград у целей не меняются); «В архив».
7. **Расписание** — каждый период-турнир — карточка; «+ добавить турнир», статус, тип периода, даты; «Копировать в остальные» (коды турниров у целей не меняются); «В архив».
8. Сохранить: «Скачать все JSON» (снимок) и/или экспорт CSV (B10).

*Коды:* `REWARD_CODE` / `TOURNAMENT_CODE` строятся из кода конкурса с префиксом `r_` / `t_` — вводится только **окончание**; для товаров (ITEM) — `ITEM_` + окончание. В JSON сохраняется полный код и отдельно окончание.

### B3. Правка существующих конкурсов из снимка

1. «Открыть сохранённые настройки (JSON)» или внизу «Импорт JSON» → снимок.
2. Найти конкурс — поиск/фильтры справа (B8) — и открыть его в списке слева. Для ITEM — выбрать сам конкурс (общие части) или конкретный товар под ним (его пара «связь + награда»).
3. Перейти к нужному шагу чипом вверху, поправить поля.
4. Скачать снимок и/или CSV.

### B4. Несколько конкурсов

«Добавить конкурс» — ещё один конкурс со своими группами/наградами/турнирами. Все конкурсы проекта — в списке слева; выгрузка по умолчанию — всех активных (или только отмеченных — B9).

### B5. Копирование конкурса

«Копировать конкурс» слева → окно: отметить, что взять — группы, связи + награды, турниры (по отдельности) → «Создать копию». Затем задать новый код конкурса и поправить отличия.

### B6. Удаление и архив

- «В архив» у группы / индикатора / пары / турнира — часть уходит в **архив**, а не пропадает. Весь конкурс — значок удаления у конкурса в списке слева → «Переместить конкурс в архив?» → OK.
- Посмотреть архив — фильтр **«Архив»** справа: одна строка на конкурс (код и число удалённых R · T · G).
- **«Восстановить…»**: всё из архива конкурса или только выбранные типы/разделы. При совпадении кода награды/турнира — выбрать: оставить текущую / заменить / восстановить рядом. Группы и индикаторы добавляются.
- «Удалить безвозвратно» — стереть архив конкурса навсегда.
- В CSV архив не попадает; в JSON сохраняется отдельно.

### B7. Стенды PROM / PSI

- У каждого конкурса — метки стенда (PROM синий, PSI фиолетовый; выключенные — серые) на карточке, в строках и в списке слева; меняются на шаге «Конкурс» («Стенд конкурса»).
- Фильтр «Стенд» справа (по умолчанию только PROM) и «только PROM / только PSI».
- CSV по умолчанию — строки с меткой PROM.

### B8. Поиск и фильтры

Справа, все блоки одновременно («И»):
- **Поиск** по коду и названиям (конкурс, награды, турниры) — «Начинается с» / «Содержит» / «Равно».
- **Тип**: Турниры / Награды / Архив.
- **Бизнес-блок**: KMMMB, KMKKSB, AKMKKSB, CSM, «Остальные», «Пусто».
- **Тип награды**: Награда / Товар / Метка / Кристалл, «Нет награды».
- **Статус турнира**: Активный, Подведение, Завершён, Отменён, Удалён, «Нет турниров».
- **Дата в периоде**: календарь + «Начало года» / «Конец года» / «Бесконечный»; «Сбросить дату».
- **Среда** (ПРОМ / ТЕСТ), **Стенд** (PROM / PSI).
- У каждого блока мини-кнопки «все» / «снять»; внизу панели — «Сбросить все фильтры» / «Установить все» (поиск не меняется).

### B9. Выбор конкурсов для выгрузки

«Выбрать» слева → у конкурсов появляются галочки; иконки рядом — «отметить все видимые» (с учётом фильтров и поиска) и «снять все». Пока режим включён и отмечены не все — «Скачать все JSON» и CSV выгружают **только отмеченные** (без архива). Фильтры не сбрасывают уже сделанные отметки.

### B10. Выгрузка

- **«Скачать все JSON»** — снимок: активные конкурсы и архив раздельно (`spod_fill_<дата>.json`).
- **«Скачать все CSV»** — 6 файлов: `CONTEST`, `REWARD`, `REWARD-LINK`, `GROUP`, `INDICATOR`, `SCHEDULE` (`… (PROM) FORM_FILL_<дата>.csv`, `;`, UTF-8 с BOM). В Chrome — выбор папки, в остальных браузерах — очередью скачиваний (разрешите множественные загрузки).
- Кнопки **CONTEST / REWARD / LINK / GROUP / INDICATOR / SCHEDULE** — по одной таблице.
- Только активные конкурсы; архив в CSV не попадает.

### B11. Сброс

«Сброс» внизу — вернуть конкурсы к значениям по умолчанию из каталога (с подтверждением). Перед этим скачайте JSON, если данные нужны.

## Часть C. Общий трейс-лог и разбор сбоев

Если что-то ведёт себя странно (страница перезагрузилась, пропали данные, кнопка не срабатывает) — соберите журнал.

1. На панели сверху справа — **«Лог»**: включить (станет красным). Запись идёт **сразу во всех областях**: и в оболочке (переключение вкладок), и в «Подготовке REPORT», и в «Заполнении SPOD». Каждая строка помечена областью: `shell`, `report`, `fill`.
2. Повторить действия до сбоя.
3. Кнопка со стрелкой (число строк) — скачать **весь** журнал `spod_edit_trace_<дата>_<время>.txt`. Каждое нажатие сохраняет журнал целиком.
4. Если страница сбросилась — журнал уцелел (каждая запись сразу сохраняется в браузере), а в нём строка **«прошлая сессия … НЕ ЗАВЕРШЕНА ШТАТНО»**: строки перед ней — то, что происходило перед сбоем. После перезагрузки лог выключен — включите снова, если нужно продолжить.
5. **Выключить** — ещё раз нажать «Лог» (серый). **Очистить** — корзина: удаляет журнал, режим не меняет.

При открытии страницы лог всегда выключен.

## Часть D. Частые вопросы

**Переключился на другую вкладку — не пропадёт ли то, что я сделал?**
Нет. Обе программы работают параллельно; вкладка только показывает нужную. Всё остаётся как было, пока открыта страница.

**Данные одной программы видны в другой?**
Нет, программы независимы: турниры/источники REPORT и конкурсы SPOD — разные данные. Обмен — через файлы (например, CSV из «Заполнения SPOD» и REPORT из «Подготовки REPORT» загружаются в SPOD).

**Почему при открытии всегда «Подготовка REPORT»?**
Так задано: основная ежедневная работа — подготовка REPORT. «Заполнение SPOD» — в одном нажатии.

**Нажал «Назад» — появилось «Назад отключён».**
Так и должно быть: переход назад перезагрузил бы страницу, и данные обеих программ пропали бы. Чтобы уйти — закройте вкладку (сохранив нужное).

**Можно открыть программы отдельно, как раньше?**
Да: `common/web-report/report_app.html` и `common/web-fill-full/game_fill_settings.html` работают как прежде; копии внутри объединённой страницы — `web-SPOD-Edit/report/` и `web-SPOD-Edit/fill/` — тоже открываются отдельно.

**В «Заполнении SPOD» каталог «встроенный» — это нормально?**
Да. Страница открыта с диска, и браузер не даёт ей прочитать `catalog.json`; используется встроенная копия каталога (та же). Сообщение «Встроенный каталог · выберите старт» — ожидаемое.

**Черновик «Заполнения SPOD» — общий с отдельной страницей web-fill-full?**
Черновик хранится в браузере под тем же ключом, что и у отдельного web-fill-full, поэтому в том же браузере «Продолжить черновик» обычно подхватывает незавершённый проект и отсюда, и там (для страниц, открытых с диска, это зависит от браузера). Надёжный способ перенести работу — «Скачать все JSON» и «Импорт JSON».

Остальные вопросы по каждой программе — в [`WEB_REPORT_USER_GUIDE.md`](WEB_REPORT_USER_GUIDE.md) («Частые вопросы») и [`../common/web-fill/README.md`](../common/web-fill/README.md).
